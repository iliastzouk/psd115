# Roadmap

Κοινή πηγή αλήθειας για τις φάσεις του project. Διαβάζεται πριν από κάθε νέα φάση και ενημερώνεται όταν μια φάση γίνει
merge. Λεπτομέρειες υλοποίησης ανά φάση: `docs/progress-migration.md`.

## Στόχος

Μία εφαρμογή μελέτης για τα μαθήματα του τρέχοντος εξαμήνου, με κοινό συμβόλαιο περιεχομένου και προόδου και ανεξάρτητη
πρόοδο ανά μάθημα:

| Κωδικός | Μάθημα |
|---|---|
| PSD125 (εναλλακτικός κωδικός PSD124) | Κοινωνική Ψυχολογία |
| PSD200 | Αναπτυξιακή Ψυχολογία Ι |
| PSD210 | Θεωρίες Προσωπικότητας |
| PSD215 | Εκπαιδευτική Ψυχολογία |
| PSD110 | Εισαγωγή στην Ηθική |

Το PSD115 μένει ως regression case του κοινού μηχανισμού.

## Απόφαση για την παλιά (legacy) πρόοδο

Ο ιδιοκτήτης του project επιβεβαίωσε ότι δεν υπάρχει αποθηκευμένη πρόοδος που χρειάζεται διατήρηση. Άρα:

- Κανένα migration από τα `psd115-*` στο νέο store.
- Κανένα frozen legacy baseline για χρήστες και κανένα τεχνητό event από παλιούς αθροιστικούς μετρητές.
- Καμία συμβατότητα με παλιά progress exports.
- Κανένα legacy backend ή dual-write path μόνο για backward compatibility.
- Η νέα πρόοδος ξεκινά καθαρή και καταγράφει μόνο πραγματικές ενέργειες.
- Theme και disclaimer είναι ρυθμίσεις, όχι πρόοδος· αλλάζουν μόνο με χωριστή αιτιολόγηση.
- Ο legacy κώδικας αφαιρείται μόνο όταν όλες οι runtime εξαρτήσεις του έχουν αντικατασταθεί και ελεγχθεί.

## Κατάσταση (στο `main`, μετά το PR #17)

- Ενεργή πρόοδος: `main.jsx` → `createProgressService` με `createLegacyProgressBackend` (κλειδιά `psd115-*`) και τον adapter
  του PSD115· ένα μάθημα.
- Νέα υποδομή (`progressStore`: `study-progress-events-v1` / `study-progress-state-v1`, events με global ids
  `<courseId>/<id>`): υπάρχει, αλλά χρησιμοποιείται μόνο από shadow/migration, που είναι κλειστά στο production. ΔΕΝ είναι
  ενεργή πηγή προόδου.
- Μελέτη και εμφάνιση προόδου: παίρνουν το μάθημα από τη διαδρομή και το περιεχόμενο από το `STUDY_CONTENT` (Φάση 5).
- Περιεχόμενο μελέτης (`STUDY_CONTENT`) και routing περιεχομένου (`routing/catalog.js`): μόνο το PSD115. Τα άλλα μαθήματα
  υπάρχουν μόνο στον ακαδημαϊκό κατάλογο.

**Ανοιχτή απόφαση:** ο σύμβουλος προτείνει να μη χωριστούν οι Φάσεις 6–8 σε πολλά μικρά PR πριν φανεί πρόοδος στα
μαθήματα, αλλά να γίνει ένα foundation PR (νέα αποθήκευση πολλών μαθημάτων + κοινό συμβόλαιο) και στη συνέχεια το πέρασμα
του υλικού των πέντε μαθημάτων με την ίδια διαδικασία. Μάθημα που δεν έχει περαστεί πλήρως δείχνει σαφή κατάσταση ελλιπούς
υλικού — όχι ψεύτικες ερωτήσεις, λανθασμένα στατιστικά ή υπόσχεση αποθήκευσης.

## Κανόνες

- Μην ξεκινάς καμία φάση χωρίς ρητή έγκριση· πρώτα πλάνο, μετά κώδικας.
- Tests πρώτα, μικρά commits, τεκμηρίωση, PR ανοιχτό για review. Κανένα merge χωρίς ρητή εντολή.
- Τα production flags (shadow/migration) μένουν κλειστά μέχρι να εγκριθεί το αντίστοιχο rollout.
- Κανένα περιεχόμενο ή δεδομένο που δεν έχει επιβεβαιωθεί από πηγές.
- Μην θεωρείς ότι η νέα υποδομή είναι ενεργή επειδή υπάρχουν τα modules της: έλεγξε το `main.jsx`.
